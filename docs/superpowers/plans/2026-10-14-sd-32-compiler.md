# SD-32 Compiler Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Compile SD1 Zak into a source-located AST or structured diagnostics.

**Architecture:** Cache a Lark LALR parser, transform its tree to explicit dataclasses, and validate the AST in a separate semantic pass. Expose one compilation entry point for SD-34 and the backend.

**Tech Stack:** Python 3.12+, Lark 1.3.1, pytest.

**Spec:** `docs/superpowers/specs/2026-10-14-sd-32-compiler-design.md`

## Global Constraints

- Existing `compiler/src/grammar.txt` is the syntax source of truth.
- No implicit conversion, including bool/int; map keys are I or S.
- Diagnostics use one-based line/column and stable codes.
- No transpilation or execution; comprehensions are parsed but semantically unsupported.
- Preserve the SD-35 commit and existing `.gitignore` edit; use a separate SD-32 branch.
- All 15 fixtures and three sample references must compile; warmed compilation target is under 50 ms per program.

## Review Focus

- Omitted slice endpoints must retain their positions rather than swap lower and upper bounds (Task 1).
- Bool literals must remain distinct from integers through type checking (Task 2).
- Empty nested collections need contextual element types (Task 2).
- Function and loop scopes must prevent name leakage and invalid control flow (Task 2).
- Malformed or deeply nested input must return diagnostics rather than raise (Task 3).
